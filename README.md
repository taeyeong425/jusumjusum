## 조작

**수집** — 배그(PUBG)식: 시점은 항상 마우스, 고르기는 조준점 / 가방

| 입력 | 동작 |
|---|---|
| 마우스 움직이기 | 시점 돌리기 (웹은 처음에 화면을 한 번 클릭) |
| [F] · 클릭 | 가운데 조준점에 있는 것 → 길을 찾아 걸어가서 줍기 · 뜯기 (원형 게이지 + 움켜쥐는 손) |
| [Tab] | 가방 — 커서가 풀리고 「근처 5m」 목록에서 골라 줍기 (걸으면서도 됨) |
| Esc | 커서 풀기 (「수집 끝내기」 버튼 등) · 다시 화면 클릭하면 시점 조작 |
| WASD · Space | 이동 · 점프 (객차·화물칸·차는 걸어가면 폴짝 올라탄다 · 미끄럼틀은 계단으로) |
| 휠 | 줌 |
| 1~0 | 핫바 칸 고르기 |
| [Q] | 고른 칸 버리기 (지나가도 자동으로 안 주워진다) |

편의 보정: **길찾기(A*) — 건물 · 울타리를 돌아서 간다 (클릭 도달률 70% → 100%)** · 가속/감속 · 코요테 타임 0.12초 · 점프 버퍼 0.15초 · 조준점 48px 관용 · 움직이는 차 · 기차는 3.2m에서 잡기 · 무릎 높이 턱 자동 오르기 · 남은 30·10·5초 경고음 · 착지 · 줍기 찌그러짐

**조립** — 축 없는 직접 조작

| 입력 | 동작 |
|---|---|
| 덩어리 끌기 · Shift+끌기 | 아래 것 위에 얹기 · 옆면에 대면 딱 붙이기 · 높이만 |
| 「크기」 손잡이 끌기 | 전체 크기 |
| 「회전」 손잡이 끌기 | 끄는 방향으로 자유 회전 |
| 빈 곳 끌기 · 우클릭 끌기 · 휠 · 가운데 버튼 | 시점 회전 · 줌 · 이동 |
| Q / E · T | 45° 돌리기 · 똑바로 |
| 1~0 | 색 |
| Del · Ctrl+Z · Ctrl+Y · F | 내리기 · 되돌리기 · 다시 · 시점 이동 |
| Alt (누른 채) | 맞춤 보정 끄기 |

맞춤 보정 (자석): 옆면 붙이기(밑면·가운데 맞춤) · 근처 덩어리와 가운데·모서리 줄 맞춤(파란 점선) · 크기 손잡이는 옆 덩어리 너비·높이 또는 0.5배 단위에 맞춤 · 회전은 놓을 때 반듯한 방향 12° 안이면 딱

**전시** — 별 위를 끌어 0.0~5.0 · ←/→ 0.1씩 · Enter 다음 작품

### 덩어리 변형

같은 종류도 비율이 다른 버전이 처음부터 있다. 조립에서는 **전체 크기와 회전만** 바꾼다.
납작한 원기둥이 필요하면 차 바퀴(「바퀴」)를, 긴 원기둥이 필요하면 가로등(「기둥」)을 뜯어 와야 한다.

| 종류 | 변형 |
|---|---|
| 원기둥 | 원기둥 · 바퀴 · 기둥 · 동전 · **육각기둥 · 삼각기둥 · 화분** |
| 구 | 공 · 럭비공 · 접시 · **보석** · 알 |
| 링 | 링 · 타이어 · 가는 링 · **네모 링 · 반달 아치** |
| 판 | 판 · 넓은 판 · 좁은 판 · 긴 판 · **둥근 판 · 별 판 · 하트 판** |
| 육면체 | 정육면체 · 벽돌 · 기둥 블록 · **ㄴ자 · 계단 · 십자 블록** |
| 막대 | 막대 · 짧은 · 긴 · **ㄱ자 · T자** |
| 원뿔 · 반구 · 캡슐 · 쐐기 · 감자 | **피라미드 · 오각뿔 · 버섯 갓 · 콩 · 지붕 · 울퉁 감자** 등 |

굵은 글씨는 생김새 자체가 다른 변형 (같은 종류로 판정되지만 메시가 다르다). 12종 × 2~7개, `scripts/data.gd` VARIANTS

### 검수 반영

- 할당량 ★ 상한 **4.0** — ★5 1인 1개 제한 하에서 ★4.5 기준은 수학적으로 도달 불가였다
- 기본 선반 = **육면체만** 1인당 5개 보장 — "직선 기근"과 "항상 넉넉"의 충돌 해소
- 동점 규칙 — 상위 절반 = 나보다 *엄격히 높은* 작품이 절반 미만 / 꼴찌만 아니면 = 나보다 *엄격히 낮은* 작품이 하나라도 있음

### 봇 평가에 대해

봇은 작품을 타겟 템플릿과 비교해 "얼마나 닮았나"를 근사한다 (`scripts/judge.gd`).
같은 타겟 고품질 ≈ 0.70~0.90 / 다른 타겟으로 만든 것 ≈ 0.37~0.58 / 무작위 더미 ≈ 0.28~0.39.
사람의 감상을 대신하는 장치라 **틀릴 수 있다**. 실제 게임은 사람끼리 평가한다.

|---|---|
| 0.40 | 4.23 |
| 0.60 | 4.49 |
| 0.75 | 4.42 |
| 0.90 | 4.67 |

v0.3부터 실제 판은 **무조건 3라운드**(통과 수와 등수로 결과). 이 시뮬레이션은 할당량 곡선 난이도 확인용으로 "연속 통과 라운드"를 잰다.

봇도 사람과 같은 규칙(모양 고정 · 크기와 회전만)으로 만든다.

기획서 목표 밴드(평균 4~6)의 하단.

## 개발

```bash
# 에디터로 열기
godot -e project.godot

# 자동 플레이 테스트 (전 페이즈를 봇으로 3라운드)
godot --headless -- --autotest
# 시나리오 테스트: 올라타기 · 미끄럼틀 · 조립 맞춤 · 클릭 도달(reach) · 손 연출 · 가방(창 모드)
.tools/godot.sh 60 --headless -- --scenario=ride   # slide · build · reach · hand · bag

# 판정·밸런스 테스트
godot --headless -s res://tests/test_judge.gd
godot --headless -s res://tests/test_balance.gd

# 웹 빌드 (custom_template 경로에 web_nothreads 템플릿 필요)
godot --headless --export-release "Web" build/web/index.html
node .tools/serve.js   # → http://localhost:8060
```

`main` 브랜치에 푸시하면 GitHub Actions가 웹 빌드를 만들어 GitHub Pages로 배포한다.
